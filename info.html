Algorithm Information

A* Search

An informed, best-first search that expands the node minimizing f(n) = g(n) + h(n) — the cost already paid plus an estimate of the cost still owed.

Type
Informed (heuristic) search, best-first
Evaluation function
f(n) = g(n) + h(n)
Time complexity
O(bd) worst case
Space complexity
O(bd) — keeps every generated node
Completeness
Complete on finite state spaces with positive step cost
Optimality
Optimal when h(n) is admissible (and consistent for graph search)

Description

A* Search is a graph-search algorithm that finds the lowest-cost path from a start state to a goal state by combining two pieces of information at every candidate node: g(n), the exact cost of the path taken so far to reach node n, and h(n), a heuristic function estimating the cheapest remaining cost from n to the goal. At each step it expands the node with the smallest f(n) = g(n) + h(n) from the frontier, which lets it combine the guaranteed optimality of Uniform Cost Search with the speed of a well-informed Greedy Best-First Search.

Working Principle

The frontier (open list) is kept as a priority queue ordered by f(n). On each iteration:

  1. Pop the node with the lowest f(n) from the frontier and move it to the explored set (closed list). If it is the goal state, stop — the path reconstructed by following parent pointers back to the start is the solution.
  2. Otherwise, generate its successors by sliding the blank tile into each adjacent position.
  3. For each successor, compute g(n) = g(parent) + 1 (each slide costs 1) and h(n) using the selected heuristic, then push it onto the frontier — unless a cheaper path to that same state is already known, in which case it is skipped or updated (relaxed).
  4. Repeat until the goal is popped from the frontier or the frontier is empty (no solution).

In this implementation the frontier is a binary min-heap keyed on (f, h), and two heuristics are selectable:

  • Misplaced Tiles — counts tiles that are not in their goal position (blank excluded). Admissible because every misplaced tile needs at least one move to be fixed.
  • Manhattan Distance — sums, over every tile, the number of grid rows plus columns it is away from its goal position. Admissible and dominates Misplaced Tiles (it is always ≥ Misplaced Tiles), so it typically expands far fewer nodes.

Advantages

  • Guarantees the shortest (least-cost) solution when the heuristic is admissible.
  • Expands far fewer nodes than uninformed strategies like BFS or Uniform Cost Search, because the heuristic actively guides the search toward the goal instead of exploring uniformly outward.
  • Flexible: swapping in a better (tighter) admissible heuristic, such as Manhattan Distance over Misplaced Tiles, immediately improves performance without changing the algorithm itself.

Limitations

  • Space complexity is exponential in the worst case — every generated node is kept in memory, which becomes the practical bottleneck long before time does.
  • Solution quality depends entirely on the heuristic: a poor or inadmissible heuristic can make A* behave like an uninformed search, or even return a suboptimal solution.
  • Computing the heuristic adds per-node overhead, which can outweigh the benefit on very shallow or trivially small search spaces.
